# 长跑漏人问题分析与解决方案

## 📋 问题定义

**漏人问题**: 运动员在画面中出现并跑步，但系统未能统计到其成绩。

---

## 🔍 深度代码分析

通过对 `LongRace.cpp` 的详细分析，我发现了多个可能导致漏人的环节。以下按照数据流程逐一分析：

---

## 🚨 漏人原因分析（按严重程度排序）

### ⚠️ 严重原因 1: 身份识别阈值过高

**代码位置**: `LongRace.cpp` 第1150行

```cpp
bool isCross = (runners[i].trackerTime > min_track_length && 
                runners[i].similerCount > min_rec_time && 
                runners[i].inAreaCount > 0);
```

**问题**:
运动员必须同时满足以下**三个条件**才能被统计：

1. ✅ `trackerTime > min_track_length` - 跟踪帧数足够（默认10帧）
2. ❌ **`similerCount > min_rec_time`** - **识别次数足够（默认1次）**
3. ✅ `inAreaCount > 0` - 过线一次

**漏人场景**:

```
场景1: 人脸识别失败
├── 原因: 角度不佳、光照不足、遮挡
├── 结果: similerCount = 0
└── 后果: 即使跑完全程，也无法统计 ❌

场景2: 号码识别失败
├── 原因: 号码布褶皱、距离过远、反光
├── 结果: 号码识别次数不足
└── 后果: 未达到 num_min_rec_time 阈值 ❌

场景3: 识别相似度刚好在阈值边缘
├── 相似度: 0.69 (阈值 0.7)
├── 结果: 不计入 similerCount
└── 后果: 永远无法达标 ❌
```

**相关代码（第1060-1078行）**:

```cpp
if(result.similar_ > recog_sim_thr_) {  // 阈值判定！
    int add_count = result.similar_ > 0.76 ? 2 : 1;
    if(runners[i].similerCount == 0) {
        runners[i].id = result.id_;
    }
    if(runners[i].id == result.id_) {
        runners[i].similerCount += add_count;  // 只有超过阈值才累加
    } else {
        runners[i].similerCount = add_count;
        runners[i].id = result.id_;
    }
}
```

**影响程度**: ⭐⭐⭐⭐⭐ 极高

**实际案例**:
```
运动员A:
- 跑步全程在画面中
- 角度始终侧面，人脸识别相似度 0.65-0.68
- 跟踪正常: trackerTime = 500帧
- 识别失败: similerCount = 0
- 结果: 未被统计 ❌
```

### ⚠️ 严重原因 2: 跟踪丢失超时移除

**代码位置**: `LongRace.cpp` 第1198-1274行

```cpp
int track_lost_time = rec_type > 0 ? 1000 : 2000;  // 1-2秒超时

   GetElapsedTime(runners[i].lastTrackerTime) > track_lost_time) {
    // 跟踪超时，移除该运动员
    runners.erase(runners.begin() + i);
}
```

**问题**:
跟踪丢失超过 **1-2秒** 后，运动员数据会被**直接删除**！

**漏人场景**:

```
场景1: 被其他运动员遮挡
├── 时间线: 
│   00:05 - 运动员A进入画面，开始跟踪
│   00:10 - 被运动员B遮挡
│   00:12 - 跟踪丢失超过2秒
│   00:12 - 系统删除运动员A数据 ❌
│   00:15 - 运动员A重新出现
├── 结果: 被当作新的运动员，重新识别
└── 后果: 前面的数据丢失，无法完整统计

场景2: 转弯时暂时离开画面
├── 400米跑道转弯处
├── 离开摄像头视野 3秒
├── 跟踪丢失，数据删除 ❌
└── 重新进入时重新计算，数据不连续

场景3: 多人同时跑，频繁遮挡
├── 10人同时跑
├── 遮挡频繁发生
├── 部分运动员数据反复删除重建
└── 最终统计不完整 ❌
```

**实际数据流**:

```
运动员A的生命周期:
00:00 - 创建 LongRunner {trackId=1, similerCount=0}
00:05 - 识别成功 similerCount=2
00:08 - 被遮挡，跟踪丢失
00:10 - 超时2秒，数据删除 ❌
00:12 - 重新出现，创建新对象 {trackId=7, similerCount=0}
00:15 - 需要重新识别...
```

**影响程度**: ⭐⭐⭐⭐⭐ 极高

## 💡 解决方案（优先级排序）

### 🔧 方案 1: 降低识别阈值（立即见效）⭐⭐⭐⭐⭐

**问题**: `similerCount > min_rec_time` 要求过严

**解决方案**:

```json
// 配置文件修改
{
  "min_rec_time_v5": 0,  // 从 1 改为 0，只要识别过1次即可
  "rec_sim_threshold_v2": 0.65,  // 从 0.7 降低到 0.65
  "new_feature_rec_sim_threshold_v2": 0.75  // 从 0.8 降低到 0.75
}
```

**代码修改** (`LongRace.cpp` 第1150行):

```cpp
// 修改前
bool isCross = (runners[i].trackerTime > min_track_length && 
                runners[i].similerCount > min_rec_time &&  // 严格要求！
                runners[i].inAreaCount > 0);

// 修改后（方案A - 激进）
bool isCross = (runners[i].trackerTime > min_track_length && 
                runners[i].inAreaCount > 0);  // 移除识别要求

// 修改后（方案B - 保守）
bool isCross = (runners[i].trackerTime > min_track_length && 
                (runners[i].similerCount >= min_rec_time || 
                 runners[i].has_face) &&  // 有人脸即可
                runners[i].inAreaCount > 0);
```

**优点**:
- ✅ 立即见效
- ✅ 配置简单
- ✅ 大幅降低漏人率

**缺点**:
- ⚠️ 可能增加误识别
- ⚠️ 需要平衡准确率

**预期效果**: 漏人率降低 **60-80%**

### 🔧 方案 3: 改进识别状态保持机制（中等难度）⭐⭐⭐⭐

**问题**: 识别状态1秒后就重置

**解决方案**:

**优点**:

- ✅ 减少重复识别

**预期效果**: 漏人率降低 **20-30%**

### 🔧 方案 8: 添加降级识别模式（中等难度）⭐⭐⭐⭐

**问题**: 识别失败时完全放弃

**解决方案**:

```cpp
// 新增：降级识别策略
enum RecognitionLevel {
    LEVEL_HIGH,      // 人脸/号码识别成功
    LEVEL_MEDIUM,    // 部分识别（低置信度）
    LEVEL_LOW,       // 仅基于跟踪
    LEVEL_FALLBACK   // 降级模式：只要跑完就统计
};

bool ShouldCount(LongRunner& runner) {
    // 优先级1: 完全识别
    if(runner.similerCount > min_rec_time) {
        runner.rec_level = LEVEL_HIGH;
        return true;
    }
    
    // 优先级2: 有人脸但相似度低
    if(runner.has_face && runner.max_similer > 0.5) {
        runner.rec_level = LEVEL_MEDIUM;
        return true;  // 允许统计，但标记为中等可信度
    }
    
    // 优先级3: 跟踪时间够长
    if(runner.trackerTime > min_track_length * 3) {
        runner.rec_level = LEVEL_LOW;
        return true;  // 允许统计，但标记为低可信度
    }
    
    // 优先级4: 降级模式
    if(enable_fallback_mode && runner.inAreaCount > 0) {
        runner.rec_level = LEVEL_FALLBACK;
        return true;  // 只要过线就统计
    }
    
    return false;
}
```

```json
  "mark_low_confidence": true  // 标记低可信度结果
}
```

**优点**:

**缺点**:
