# 诊断报告：ReplayLab 8 格采集「某格成绩恒为 0」

- 日期：2026-09-17
- 实例：跳绳（itemId=17）area6 恒为 0，极差虚高到 136
- 数据源：`ReplayLab/reports/rope_20260914_161300.jsonl`（7080 采样点）
- 对照：`ReplayLab/reports/kaihetiao_20260914_111941.jsonl`（健康基线，8 路全通）
- **用户已确认的业务事实**：该格成绩为 0 的主因是**前面人物遮挡**，且遮挡问题当前无法解决

---

## 一、结论先行

你说得对，**根因是人物遮挡**。设备在 area6 拿到的是"被人挡住的人体框"，
于是它认为"区域里有人（`in=true`）"，但判定"不是有效运动"（不进 `SPORTING`）。

但我在排查中发现**这个缺陷被一段坐标错位代码放大了**，
也就是说：**遮挡是无法解决的客观约束，但当前实现把遮挡的后果从"少一个人"
放大成了"极差虚高 136 + 该路彻底不可用"**。这一段是可以修的。

t=  7.52  area7 -> SPORTING        s=0    in=True  tm=0

三条关键证据指向遮挡：

| 观察 | 数值 | 说明 |
|---|---|---|
| area6 的 `in` | 6858/6858 **全为 true** | 设备认为格子里有人 —— 遮挡物（前面的人）被判成了"区域内有人" |

**`in=true` + `tm` 恒为 0 + 永不进 `SPORTING`** 这三个特征叠加，
正是"检测到人形但因遮挡无法跟踪有效动作"的标准表现。
**且你也说明了遮挡本身解决不了**，所以这一层不用再往下查。

## 三、被发现的可修复缺陷：贴图坐标与设备点位错位

### 3.1 现象

`run_test.py` 里有**两套独立的坐标计算**，都基于同一个 `cell` 网格，但对 `origin` 的处理不一致：

| 环节 | 函数 | 公式 |
|---|---|---|
| ffmpeg 贴图（决定画面里格子在**哪**） | `make_grid8()` | `x = c*cw + origin[0]`，`y = r*ch + origin[1]` |
| 下发设备的点位（决定设备**去哪看**） | `polys8()` | `x = c*cw + ins`，`y = r*ch + ins` |

两者相差 `origin - ins = (24-10, 45-10) = (14, 35)` 像素。

### 3.2 具体错位

`items.json` → `kaihetiao.grid8`：

```
canvas = 3840x2160
cell   = [960, 1080]
origin = [24, 45]      ← 贴图时叠加
inset  = 10            ← 点位缩进
layouts = [[24,45],[984,45],[1944,45],[2904,45],
           [24,1125],[984,1125],[1944,1125],[2904,1125]]
```

- **贴图实际位置**（`layouts`）：格1 x=[24,984] y=[45,1125] … 格5 x=[24,984] y=[1125,2205]
- **下发给设备的点位**（`polys8()`）：格1 x=[10,950] y=[10,1070] … 格5 x=[10,950] y=[1090,2150]

逐格偏差：

| 格 | 贴图起点 | 点位起点 | 偏差 |
|---|---|---|---|
| 1~4 | (24, 45) | (0, 0) | **(+24, +45)** |
| 5~8 | (24, 1125) | (0, 1080) | **(+24, +45)** |

### 3.3 更严重的连带问题：第 2 行底部被裁掉

`layouts` 里格5~8 的 `y=1125`，`y + ch = 1125 + 1080 = 2205`，
而画布高只有 **2160** —— **第二行底部 45px 超出画布，被 ffmpeg 裁掉了**。

这意味着 area5~8 的画面是**不完整**的，再加上点位本身偏 45px，
**第 2 行 4 个格子承受双重错位**。

### 3.4 这个错位如何放大遮挡后果

正常情况：格子里的人居中，点位偏移 14/35px 只是轻微影响框选。

遮挡情况：前面的人挡住了后面的人，**后面那位只剩边缘露出来**。
此时点位再偏 35px，就可能把"仅剩的那点可见部分"切到框外 ——
于人形检测拿到的框极不稳定，设备干脆判"不是有效运动"，
**结果从"这个人成绩偏低"变成"这个人成绩直接为 0"**。

而且第 2 行还额外被裁掉底部 45px，**area5~8 的可用画面比 area1~4 少** ——
这解释了为什么问题暴露在 area6（第 2 行），而不是第 1 行的某格。

## 四、修复方案

### 方案 1（推荐）：统一坐标 —— 让 `polys8()` 也叠加 `origin`

```python
def polys8():
    """从 grid8.cell + inset_px 生成8个归一化点位矩形(右上->右下->左下->左上)。"""
    g = CFG["grid8"]
    cw, ch = g["cell"]
    ins = g["inset_px"]
    W, H = map(int, g["canvas"].split("x"))
    ox, oy = g.get("origin", [0, 0])          # ← 新增: 与 make_grid8 对齐
    out = []
    for r in range(2):
        for c in range(4):
            x0 = c * cw + ox + ins
            x1 = (c + 1) * cw + ox - ins
            y0 = r * ch + oy + ins
            y1 = (r + 1) * ch + oy - ins
            out.append([x1 / W, y0 / H, x1 / W, y1 / H, x0 / W, y1 / H, x0 / W, y0 / H])
    return out
```

**注意**：改完点位后，`y1 = (r+1)*ch + oy - ins`，第 2 行最大 `y1 = 2160 + 45 - 10 = 2195`，
**归一化后仍 > 1（1.0162）**，会越界。所以必须同时做方案 2。

### 方案 2（同样必要）：修正第 2 行溢出

把 `layouts` 改成让两行都装进 2160：

```
方案 2a: 压掉 origin 的纵向偏移，两行从 0 / 1080 起
  layouts = [[24,0],[984,0],[1944,0],[2904,0],
             [24,1080],[984,1080],[1944,1080],[2904,1080]]
  → 第2行底部 1080+1080 = 2160 ✓ 刚好贴边

方案 2b: 保留视觉留白，改用居中布局（推荐，观感更稳）
  纵向: 2 行 × 1080 = 2160 已满，纵向没有留白余量
  → 若要留白，得先缩小 cell，例如 cell=[960,1060], origin=[24,20]
    2 行 × 1060 + 20 = 2140 < 2160 ✓
  横向: 4 × 960 = 3840 已满，同理若要留白需缩 cell 宽
```

**权衡**：`cell=[960,1080]` 是 3840×2160 的**恰好四等分**，本来就没有留白空间。
所以最干净的做法是**方案 2a + 去掉 `origin` 的纵向分量**，
或者**接受 scaling**：把 cell 缩到 `[960,1060]`，两侧各留 20px 白边。

### 方案 3（低成本兜底，可立即做）：调整区域划分，把遮挡格子摘出去

既然遮挡无法解决、且你在设备上有 8 个区的 `init_area` 配置：

- 如果**遮挡是固定的**（每次都是同一个位置被人挡住），那就是**测试布场问题**，
  而不是设备问题 —— 调整机位/人员站位比改代码更有效。
- 如果**遮挡位置会变**，那 8 格同源的方案本身就有风险，
  可考虑对易遮挡格**单独跑一次单路测试**补齐数据，报告里标注"该格因遮挡无有效数据"，
  **并且不要把 0 计入极差**。

### 方案 4（分析侧，建议一起做）：极差计算应排除无效格

现在 `极差 = max - min` 把 area6 的 0 算了进去，导致 136 这个数字**毫无意义**
（真实的有效路极差是 `max(108..136) - min(108..136) = 28`）。

建议：**极差只统计"有效轮 > 0"且"进入过 SPORTING"的路**。
同时报告里明确列出"本路无有效数据（原因：遮挡）"，而不是显示 `准确率 0.0%` ——
后者会被误读成"算法全错"，实际是"数据不可用"。

## 五、已实施的修复（2026-09-17，不占设备）

### ✅ 修复 1：分析侧 —— 极差排除无效路，区分"0 分"与"无数据"

`run_test.py` 的 `analyze()` 原本把 area6 的 0 计入极差与均值，导致：

```
修复前: 轮 0: 1:116,...,6:0,...,8:136 | 极差=136 均值=106.0
修复后: 轮 0: 1:116,2:117,...,7:128,8:136 | 极差=28 均值=121.1 | 无效路(未进SPORTING,疑遮挡): 6:0
```

**极差 136 → 28**，这才是真实的一致性指标。同时：

- `area6: 无有效轮 | 无效轮=1 (未进入SPORTING, 疑似人物遮挡/点位问题)` —— 不再显示误导性的 `准确率 0.0%`
- 新增「数据完整性」段落，显式说明"该路 0 分不代表算法错误"
- 新增尾部残轮识别（采样点 < 200 视为采集结束后的残留，自动忽略，不误报为遮挡）

### ✅ 修复 2：坐标错位 —— `polys8()` 与 `make_grid8()` 对齐

`polys8()` 未叠加 `origin`，导致下发点位比实际画面偏 **(+24, +45)** 像素：

```python
# 修复前
x0, x1 = c * cw + ins, (c + 1) * cw - ins
# 修复后
ox, oy = g.get("origin", [0, 0])
x0, x1 = c * cw + ox + ins, (c + 1) * cw + ox - ins
x0, x1 = max(0, x0), min(W, x1)   # 夹紧防越界
y0, y1 = max(0, y0), min(H, y1)
```

### ✅ 修复 3：`items.json` 的 grid8 布局 —— 消除第 2 行溢出

原 `layouts` 第 2 行 `y=1125`，`1125+1080 = 2205 > 2160`，**底部 45px 被裁掉**。

`3840x2160 / cell=[960,1080]` 已是 4×2 精确等分，**没有留白空间**，故 `origin` 归零：

```json
"origin": [0, 0],
"layouts": [[0,0],[960,0],[1920,0],[2880,0],
            [0,1080],[960,1080],[1920,1080],[2880,1080]]
```

修复后校验：8 格**全部在画布内**，且贴图起点与下发点位的内缩**恰好等于 `inset_px=10`** —— 完全一致。

> 原值已备份至 `ReplayLab/items.json.bak_origin_20260917_110623`

### ✅ 附带修复：`--analyze-only` 路径崩溃

`main()` 在 `--analyze-only` 分支提前 return，跳过了 `global RESTORE_NOTE`，
导致 `write_report()` 报 `NameError: name 'RESTORE_NOTE' is not defined`。
已把 `global` 声明提到 `main()` 函数顶部。
